## M0.3 · 日志 `common/Logger`

### 做什么
自己写一个**轻量、线程安全**的日志（不引第三方——少依赖，且这是能讲的东西）。

### 接口设计

```cpp
// common/Logger.h
enum class LogLevel { TRACE, DEBUG, INFO, WARN, ERROR };

class Logger {
public:
    static Logger& instance();
    void setLevel(LogLevel lv);
    void log(LogLevel lv, const char* module, const char* fmt, ...);
private:
    std::mutex mu_;
    LogLevel level_ = LogLevel::INFO;
};

// 宏（自动带模块名/文件行号）
#define LOG_INFO(mod, ...)  Logger::instance().log(LogLevel::INFO,  mod, __VA_ARGS__)
#define LOG_WARN(mod, ...)  Logger::instance().log(LogLevel::WARN,  mod, __VA_ARGS__)
#define LOG_ERROR(mod, ...) Logger::instance().log(LogLevel::ERROR, mod, __VA_ARGS__)
```

输出格式：`[2026-07-19 21:33:05.123][INFO ][transport] sent 128 packets`

### 执行步骤
1. 写 `Logger.h/.cpp`，用 `std::mutex` 保证多线程不串行乱码
2. 时间戳精确到**毫秒**（后面测延迟要用）
3. 低于当前级别直接 return（**热路径要快**）

### 验收标准
- [x] 三个可执行启动时各打一条 INFO，格式统一、含毫秒
- [x] `setLevel(WARN)` 后 INFO 不再输出
- [x] 起 4 个线程各打 1000 条，输出**没有交错撕裂的行**

## M0.4 · 配置 `common/Config`

### 做什么
命令行参数解析（+ 可选 key=value 配置文件）。**杜绝硬编码 IP/端口/分辨率**。

### 需要支持的参数（先定这些，后续里程碑再加）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--help` | — | 打印用法 |
| `--log-level` | info | trace/debug/info/warn/error |
| `--config` | — | 配置文件路径 |
| `--listen` | 0.0.0.0:9000 | 服务端/接收端监听 |
| `--target` | 127.0.0.1:9000 | 发送目标 |

### 接口设计

```cpp
class Config {
public:
    bool parse(int argc, char** argv);        // 失败返回 false 并打印用法
    std::string get(const std::string& key, const std::string& def = "") const;
    int  getInt(const std::string& key, int def = 0) const;
    void printUsage() const;
private:
    std::map<std::string, std::string> kv_;
};
```

### 执行步骤
1. 先支持 `--key=value` 和 `--key value` 两种写法
2. 再支持 `--config file`（`key=value` 每行一条，`#` 注释）
3. **优先级**：命令行 > 配置文件 > 默认值

### 验收标准
- [x] `--help` 打印所有参数和默认值
- [x] `--log-level=debug` 能真的改变日志级别（串起 M0.3）

## M0.5 · 状态码 + 有界队列 `common/`

### 做什么
统一错误返回约定 + 项目最核心的基础设施 `BoundedQueue`。

### Status（错误处理约定）

```cpp
// common/Status.h
enum class Code { Ok, InvalidArg, IoError, NetError, Timeout, Closed, Internal };

class Status {
public:
    static Status ok();
    static Status error(Code c, std::string msg);
    bool isOk() const;
    Code code() const;
    const std::string& message() const;
};
```

**约定：模块公开接口一律返回 `Status` 或 `bool`，不跨模块抛异常。**

### BoundedQueue（重点）

```cpp
// common/BoundedQueue.h  （模板，头文件实现）
template <typename T>
class BoundedQueue {
public:
    explicit BoundedQueue(size_t cap);
    bool push(T item);   // 队满阻塞；已 close 返回 false
    bool pop(T& out);    // 队空阻塞；空且 close 返回 false
    void close();        // 唤醒所有等待者
    size_t size() const;
    size_t peak() const; // 峰值水位（后面测积压要用）
private:
    std::deque<T> q_; size_t cap_; bool closed_ = false;
    size_t peak_ = 0;
    mutable std::mutex mu_;
    std::condition_variable notFull_, notEmpty_;
};
```

> 三条铁律（阶段 4 已验证）：**队满生产者等 / 队空消费者等 / `close()` 唤醒全部**；`wait` 必须带谓词。

### 执行步骤
1. 写 `Status.h`
2. 写 `BoundedQueue.h`（模板，全部写在头文件）
3. 支持 move-only 类型（后面要塞 `unique_ptr<Frame>`）——用 `std::move` 传递

### 验收标准
- [x] `BoundedQueue<int>` 与 `BoundedQueue<std::unique_ptr<int>>` 都能编译
- [ ] 单测覆盖（见 M0.6）

## ⚠️ 常见坑提醒

1. **CMake 目录依赖**：`common` 必须在 `app/*` 之前 `add_subdirectory`，否则找不到 target。
2. **日志锁粒度**：只锁"写输出"这一段，别把格式化也锁进去（热路径会慢）。
3. **BoundedQueue 的 `wait` 必须带谓词**——虚假唤醒 + `notify_all` 会坑你（阶段 4 已踩过）。
4. **close 语义**：close 后**先让消费者把残留取完**，再返回 false；直接丢弃会丢数据。
5. **单测别写成死锁**：阻塞类测试一定加超时保护。
6. **模板类不要分 .h/.cpp**：`BoundedQueue` 全写头文件，否则链接报错。
7. **别在 M0 就想着优化**：先正确、先跑通，性能等有数据了再说（[[性能分析]] 的铁律）。
