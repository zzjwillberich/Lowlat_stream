# 实测数据存档

[M4 报告](../M4_弱网对抗.md)里每张表的原始数据。

日志（每次运行的两端完整输出，几百 KB 一轮）**不进仓库** ——
里面绝大部分是每秒重复的统计行。要看轨迹就自己跑一遍：

```bash
./scripts/m45_bench.sh g3 g4
```

## 目录

| 目录 | 内容 | 对应报告里的表 |
|---|---|---|
| `20260901_g3g4/` | g3（抖动 × 自适应，8 格）+ g4（RTT × NACK，3 格） | 三、四、五节；以及「三条被推翻的假设」里的 ①③ |
| `20260901_g4_repeat/` | g4 单跑，用来验证可复现性 | 测试记录第七轮 |

两轮都跑在 commit `24bd201`，`netem` 生效设备 `loopback0`，每格 3 个种子 × 1000 帧。
具体参数见各自的 `meta.txt`。

## 文件

- **`runs.csv`** —— 每次运行一行。**读结论要看这个而不是 summary**：
  自适应 vs 固定水位那张表的 p95 差异（3~7ms）小于单格内三个种子的散布（最大 9ms），
  只看聚合值会把噪声读成结论。
- **`summary.csv`** —— 按格聚合 + 派生指标（真丢包率、FEC 过销、render_ratio 等）。
  派生规则见 [`scripts/m45_summarize.py`](../../scripts/m45_summarize.py)。
- **`meta.txt`** —— commit / 内核 / 参数，供复现。

## 缺的那几张表

消融表（g1）、丢包率扫描（g2）、PLI（g5）、GOP 扫描（g6）的原始数据**已经丢失** ——
早期几轮的提交命令里带了 `rm -rf bench`，而 `bench/` 本来就在 `.gitignore` 里，
那个清理既多余又是破坏性的。

报告里那几张表的数字是从当时的终端输出记下来的，**结论可信但不可追溯**。
要补齐就重跑：

```bash
./scripts/m45_bench.sh g1 g2 g5 g6     # 约 25 分钟
```

重跑还顺带解决另一件事：那几张表是 **M4.6 修复之前**测的，
重跑之后就能把报告里的 build 标注去掉。
